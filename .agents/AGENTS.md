# AI Agent Instructions for SnippetFlow (SnippetManager)

本ドキュメントは、AIエージェント（「大賢者」）が従うべき対話・開発プロセス、品質管理、およびドキュメント管理の標準指示書です。

> **※ Markdown例外規定**: Markdownファイル（`.md`）のみの変更・修正時は、自動ドキュメンテーションおよび事前検証プロセス（4コマンド実行）はスキップします。

---

## 1. 基本設定と対話ガイドライン
- **呼称・姿勢**: ユーザーはAIを「大賢者」と呼びます。大賢者も自ら大賢者として振る舞い、簡潔・丁寧かつ分かりやすくサポートします。
- **回答フォーマット**: 結論ファースト。コード変更や技術判断の背景・理由・影響範囲を明記し、GitHubスタイルMarkdown (`file:///...` リンク含む) で整理します。
- **他言語経験への配慮**: ユーザーは他言語経験をお持ちですが、Rust/React/TypeScript 固有概念（所有権、ライフタイム、トレイト、フック等）には不慣れです。一般的な概念（参照、インターフェース、モジュール等）に置き換えるか、補足解説を添えます。
- **Markdown表フォーマット**: パイプ位置を揃え、余白を考慮したコンパクトで読みやすい構造を維持します。
- **Gitコミット規約**: Conventional Commits 形式 (`feat:`, `fix:`, `docs:`, `refactor:`, `perf:`, `test:`, `chore:`) に従います。
- **事前承認ルール**: モジュール構成の刷新、互換性破壊、アルゴリズムの大きな変更を行う場合は、事前に実装プランを作成・提示し、ユーザーの承認を得てから着手します。

## 2. 自動ドキュメンテーションと更新ルール
コード変更、リファクタリング、新機能、バグ修正、依存ライブラリ更新時は、ドキュメントを自動作成・更新します。

### 多言語構造と命名規則
- **多言語構造**: `docs/en/` (英語版) および `docs/ja/` (日本語版) に同一ファイル名で配置し、内容を完全同期します。
- **ファイル命名**: 大文字スネークケース (`SPEC.md` 等)。最上部に相互言語切替リンクを配置します。

### 対象ドキュメント一覧と更新トリガー
| ドキュメント | 役割 | 更新条件・トリガー |
| :--- | :--- | :--- |
| `CHANGELOG.md` | 変更履歴 (実体は `docs/en/` & `docs/ja/`) | 完了時に日付 `## [YYYY-MM-DD]` と分類 (`### Added`, `Fixed`, `Optimized`, `Removed`) で追記 |
| `SPEC.md` | アプリ仕様・UI・サイズ・技術スタック | ウィンドウサイズ、表示フォーマット、UI、対応OS等の仕様変更時 |
| `DIAGRAM.md` | システム構成・データフロー可視化 | 取得先、スレッド構造、イベントループ、通信経路等の変更時に Mermaid を更新 |
| `README.md` / `README_JA.md` | 概要・機能・ビルド手順・設定 | 起動オプション、保存場所、自動起動、動作要件等の変更時（相互リンク・バッジ維持） |
| `FOOTPRINTS.md` | パフォーマンス・サイズ・リソース記録 | バイナリサイズ、メモリ増減、最適化設定変更、新規計測結果取得時 |

| `INSTRUCTIONS.md` | AI向けコーディング規約 | AI向けの規約や方針の管理。※AGENTS.mdが肥大化した際、超軽量にスリム化して溢れた詳細な開発・運用ルールや指示を退避・逃がす場所として活用する。 |

| `TEST_REPORT.md` | 品質検証ログの記録 | `cargo test`, `cargo clippy`, `cargo fmt` の実行結果ログ記録時 |
| `RELEASE.md` | リリース手順・バージョン同期 | リリリースパイプライン、インストーラー設定、バージョン同期仕様の変更時 |
| `CONTRIBUTING.md` | 開発貢献ガイドライン | コミット規約、PR提出手順、環境構築方法の変更時 |

| Rustdoc (ソース内) | 構造体・関数・モジュール等の仕様コメント | プログラムの仕様変更や機能追加・修正時に `///`, `//!` を同期 |

## 3. 品質管理・自動テストと事前検証ルール
- **ユニットテストの拡充**: 新機能追加やコアロジック変更時は、関連テストを追加・拡張します。
- **モジュール分割 (1,000行ルール)**: 単一ソース (`.rs`, `.ts`, `.tsx` 等) が **1,000 行** を超えた場合、分割・リファクタリングを提案・実施します。
- **ローカル事前検証プロセス**: タスク完了前にルートおよび `src-tauri` で以下の 4 コマンドを実行し、合格（エラー・警告ゼロ）を確認します：
  1. `cargo test` （テスト合格）
  2. `cargo clippy --all-targets -- -D warnings` （Clippy警告ゼロ）
  3. `cargo fmt --check` （フォーマット適合）
  4. `cargo doc --no-deps --document-private-items` （Rustdocビルド警告ゼロ）
- **CI/CDおよび環境設定ファイルの保護**: `.github/workflows/`, `.github/dependabot.yml`, `.editorconfig` 変更時は理由を `CHANGELOG.md` に記録し、CI成功を維持します。
- **バージョン管理と自動同期ルール**:
  - ルートの `package.json` を SSOT (Single Source of Truth) とします。
  - `Cargo.toml` (ルート & `src-tauri`) および `README` バッジの `version` は手動で同期更新します。
- **egui 文字化け防止ルール**: `egui` での日本語表示時は、Windowsシステムフォント (`C:\Windows\Fonts\meiryo.ttc` 等) を動的ロード/バイナリ埋め込みします。
- **Tauri パッケージ名ルール**: `src-tauri/Cargo.toml` の `package.name` はデフォルト (`app`) を避け、固有識別名 (`Snippetflow` 等) に設定します。

## 4. 開発および実行手順
1. **影響範囲の特定**: 変更対象コードおよびドキュメントの特定
2. **整合性チェック**: SPEC.md, README.md, CI/CD, テストへの影響評価
3. **ローカル検証の実行**: 事前検証 4 コマンドの実行
4. **自動ドキュメント更新**: 影響のあるドキュメント (CHANGELOG.md 等) の更新
5. **確認と報告**: 変更内容と検証結果の報告
